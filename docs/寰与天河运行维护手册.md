更新时间：2026-07-26（CST）

> 本文是寰/IAP 与天河两套计算发布环境的专项说明。域名、GitHub Pages、OSS、
> `server02`、前端、备份与恢复的完整入口见
> [网站运行与运维总手册](网站运行与运维总手册.md)。

## 1. 总览

网站本身是 GitHub Pages 静态站，浏览器通过 `app.js` 读取 catalog，再加载图件。页面同时保留两个可切换的数据源：

| 数据源 | 页面标识 | catalog | 图件存放与发布方式 | 当前用途 |
| --- | --- | --- | --- | --- |
| 寰 | `huan` / “寰” | `data/current/forecast-runs.json` | 原 IAP 发布链路生成图件、上传 OSS，提交 catalog | 备用与历史来源 |
| 天河 | `tianhe` / “天河” | `data/tianhe/current/forecast-runs.json` | 天河直接生成图件、提交到 GitHub Pages | 当前主用来源 |

所有页面目前都设置了 `data-default-source="tianhe"` 和 `data-force-default-source="true"`。因此即使浏览器曾记住“寰”，打开页面时仍会优先显示天河；天河 catalog 不可用时，前端才会尝试另一来源。

```text
WRF 输出 ──> 渲染/优化 ──> catalog ──> GitHub main ──> GitHub Pages ──> iaplacs.xyz
  寰：IAP 侧                 天河：天河定时任务
```

## 2. 前端与目录约定

- `index.html`、`ningxia/index.html`、`shangrao/index.html`、`airpots/index.html`：四个入口页及默认数据源设置。
- `app.js`：读取两个 catalog、切换来源、每两分钟刷新、预览/放大/下载图件。
- `data/current/`：寰的 catalog；其中图件 URL 通常指向 OSS。
- `data/tianhe/current/`：天河 catalog 与已发布图件。
- `data/tianhe/current/maps/`：按产品族和起报时次保存天河图件，例如 `worknx_summary_YYYYMMDD_HH/`。

页面读取的服务与模型对应如下：

| 页面 | 天河模型目录 | 默认图 | 同时提供的全国图 |
| --- | --- | --- | --- |
| `/`、`/ningxia/` | `WORK_nx` | 宁夏区域 36 小时（T13–T48） | 是 |
| `/airpots/` | `WORK_yn` | 云南机场区域 36 小时及机场统计 | 是 |
| `/shangrao/` | `WORK` | 上饶区域 36 小时 | 是 |
| 无页面 | `WORK_tc` | 不发布 | 否，仅做降水备份 |

`forecast-runs.json` 是前端唯一的产品入口。不要只复制图片却不重建 catalog，也不要手改 catalog 中的文件名而不确认对应文件存在。

## 3. 寰（原 IAP 侧）运行原理

寰是原有 IAP 侧发布链路，保留作备用来源。其基本流程为：

1. IAP 侧完成 WRF 后处理并在 `data/current/maps/` 的时间目录中生成 PNG、WebP、preview WebP 和必要 JSON；
2. 上传图件到 OSS，并确认公开 URL 可读；
3. 运行 `tools/build_forecast_catalog.py`，生成 `data/current/forecast-runs.json`；
4. 仅提交 catalog/小型清单到 GitHub，GitHub Pages 更新后前端即可读取新时次。

常用脚本包括 `tools/optimize_forecast_images.sh`、`tools/build_forecast_catalog.py`、`tools/publish_worknx_ningxia_to_github.sh` 与 `tools/publish_workyn_yunnan_airports_if_new.sh`。它们仍是可复用的备用能力，但不是当前天河定时发布的入口。

维护要点：

- 保留每类最近 5 个时次；不要在发布前清空 `data/current/maps/`，否则 catalog 会丢失可选历史时次。
- 确认 OSS 图件先上传成功，再更新 catalog；否则网站会显示条目但图片 404。
- `data/current/maps/` 是服务器缓存，不要从 Mac 上批量 `git add` 或用本地旧图覆盖它。

如需临时让网站固定使用寰，在四个入口页中将 `data-default-source` 改为 `huan`；如需忽略浏览器已保存的选择则保留 `data-force-default-source="true"`。修改后应同时更新四个页面并发布。

## 4. 天河运行原理（当前主用）

天河发布器位于隐藏的生产 checkout：

```text
/fs2/home/junzhang/kerui/.iaplacs-site
```

模型输出的默认位置为：

```text
/fs2/home/junzhang/zhoubj/WORK_nx
/fs2/home/junzhang/zhoubj/WORK_yn
/fs2/home/junzhang/zhoubj/WORK
/fs2/home/junzhang/zhoubj/WORK_tc
```

核心入口是 `tools/tianhe_publish_forecast_to_github.sh`。每次执行时它会：

1. 找到每个产品族最新的数字时次，并确认 `wrfout_d01_*` 完整、稳定；默认要求文件至少 20 分钟未更新且不小于 20 GB。
2. 对 `WORK_nx` 渲染宁夏和全国图，对 `WORK_yn` 渲染云南机场和全国图，对 `WORK` 渲染上饶和全国图；36 个小时面板对应 T13–T48。
   全国图使用 NCL `CylindricalEquidistant` MapPlot 的显式地理主刻度：横轴为
   75/90/105/120/135°E，纵轴为 20/30/40/50°N。坐标文字与刻度由 NCL 绘制，
   不得在 ImageMagick 拼图阶段添加人工坐标标签；仅保留底部、左侧主刻度，不保留子刻度。
3. 将中间面板放入 `~/.iaplacs-tianhe/rendered/`，拼图完成后只保留最终产品；中间 `.panels` 不应手工发布。
4. 复制最终 PNG/JSON 至 `data/tianhe/current/maps/`，生成 WebP 与 preview WebP，最多保留每类 5 个网站时次。
5. 运行 `tools/build_tianhe_forecast_catalog.py` 重建 catalog，提交 `data/tianhe/current/` 并推送 `main`。
6. 为完整 WRF 输出创建并校验降水精简备份（`Times`、`XLAT`、`XLONG`、`RAINC`、`RAINNC`），默认各类保留 10 份。

生产 crontab 每 15 分钟运行一次：

```cron
7,22,37,52 * * * * IAPLACS_TIANHE_DELETE_COMPLETED_MODEL_RUNS=0 /fs2/home/junzhang/kerui/.iaplacs-site/tools/tianhe_publish_forecast_to_github.sh >> /fs2/home/junzhang/.iaplacs-tianhe/logs/github-publisher.log 2>&1
```

发布器使用锁目录 `/fs2/home/junzhang/.iaplacs-tianhe/publisher.lock` 防止 cron 与人工运行重叠。Git 网络临时失败时，本地提交会保留，下一次 cron 会再推送。

### 数据保留与删除规则

- 网站图件：每产品族最近 5 个时次。
- 降水精简备份：默认每产品族最近 10 份，位于 `/fs2/home/junzhang/kerui/iaplacs-precip-backups/`。
- 完整 WRF 输出：默认**不删除**，由 `IAPLACS_TIANHE_DELETE_COMPLETED_MODEL_RUNS=0` 保证。
- `WORK_tc`：不出现在网站，只按稳定文件生成降水备份；完整输出同样默认保留。

只有在明确确认空间压力、备份已验证且用户允许时，才能将 `IAPLACS_TIANHE_DELETE_COMPLETED_MODEL_RUNS` 改为 `1`。不要删除隐藏 checkout、未稳定目录或渲染缓存以外的模型目录。

## 5. 日常检查与手动操作

在天河生产 checkout 中执行：

```bash
cd /fs2/home/junzhang/kerui/.iaplacs-site
tools/tianhe_publish_forecast_to_github.sh --dry-run
tail -n 120 /fs2/home/junzhang/.iaplacs-tianhe/logs/github-publisher.log
git status --short
```

`--dry-run` 只检查发现、完整性和计划动作，不修改图件或 Git。若日志显示“incomplete”或“waiting for stable WRF output”，应等待下一次 cron，不能强行复制正在写入的 `wrfout`。

仅在修改了渲染脚本、色标、边界或版式后，才对已经发布的完整时次使用：

```bash
tools/tianhe_publish_forecast_to_github.sh --force
```

该命令会重渲染并可能发布新提交；运行前确认没有其他人工发布在进行，锁存在时不要手动删除锁目录。

本地快速检查：

```bash
node --check app.js
bash -n tools/tianhe_publish_forecast_to_github.sh
python3 -m py_compile tools/build_tianhe_forecast_catalog.py
git diff --check
```

## 6. 常见故障定位

| 现象 | 首先检查 | 处理原则 |
| --- | --- | --- |
| 网站没有新时次 | 天河日志、`--dry-run`、WRF 文件年龄/大小 | 等待文件稳定；不要发布不完整时次 |
| catalog 有新条目但图加载失败 | catalog 内 `file`/`full_file` 与仓库文件 | 重新发布完整图件和 catalog；不要只改 JSON |
| 下载原图失败 | `full_file` 是否指向实际 PNG | 保留并发布 PNG 原图；前端会回退到可显示图件 |
| 页面显示寰 | 入口页的默认属性、浏览器本地存储、天河 catalog 是否可读 | 当前应保持 `tianhe` + 强制默认；先排查天河 catalog |
| 天河无法推送 | 日志中的 Git/网络错误、隐藏 checkout 是否干净 | 不要在生产 checkout 留下未提交的 `data/tianhe` 修改；等待 cron 重试或修复认证/网络 |
| 图件样式不一致 | 使用的渲染脚本与对应 WRF 原始数据 | 从完整 WRF 重渲染；不要伪造或替换历史图 |

## 7. 本地改动与发布纪律

1. 修改网页/文档前后均先 `git pull`；天河可能同时推送数据提交。
2. 只暂存明确修改的文件，避免 `git add .`。
3. 不提交本地缓存、批量预报图、`.tmp` 或未知来源文件。
4. 天河隐藏 checkout是生产工作目录；不得删除或移动。
5. 图件中的英文、数字采用 Times New Roman，中文采用宋体（Songti SC）；新绘图脚本须保持这一字体约定。
